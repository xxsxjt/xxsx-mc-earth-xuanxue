## Client black-screen crash fixed

A client launch on MC 26.1.2 / NeoForge 26.1.2.124 crashed while building entity models during
resource reload, leaving a black screen (`abortResourcePackRecovery`, `gameLoadFinished=false`).

Cause: two models called `ModelPart.getChild` with paths that did not match the generated
part tree. `getChild` throws `NoSuchElementException` for a missing part, and that exception
happens inside `EntityModel` construction, so the whole reload aborts.

| Model | Wrong path | Actual tree |
|---|---|---|
| EmberCraneModel | `neck.getChild("head")` | `head` is under `neck > upper` |
| StonehornGoatModel | `head.getChild("left_horn")` / `right_horn` | three siblings: `left_horn_base/mid/tip`, `right_horn_base/mid/tip` |

Both are fixed. The goat's horn sway now drives the base segment, which is correct because
the mid and tip are siblings rather than children.

## Regression guard

`tools/check_model_parts.py` parses every `EntityModel` in the mod, rebuilds the part tree
from `addOrReplaceChild` calls, and asserts that every constructor `getChild` path resolves.
It reports all six models as OK. This runs in seconds and catches exactly the class of bug
that blacked out the client.

Note on the check: the tree is keyed by **part name**, not Java variable name. Generated code
binds `PartDefinition tail_tail_mid = tail.addOrReplaceChild("tail_mid", ...)`, and
`getChild("tail_mid")` is correct even though the variable is named differently. An earlier
version of the checker keyed on variable names and produced false failures.
