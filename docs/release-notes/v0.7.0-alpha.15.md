## Client black-screen crash fixed

A client launch on MC 26.1.2 / NeoForge 26.1.2.124 crashed while building entity models during
resource reload, leaving a black screen (`abortResourcePackRecovery`, `gameLoadFinished=false`).

Cause: two models called `ModelPart.getChild` with paths that did not match the generated
part tree. `getChild` throws `NoSuchElementException` for a missing part, and that exception
happens inside `EntityModel` construction, so the whole reload aborts.

| Model | Wrong path | Actual tree |
|---|---|---|
| EmberCraneModel | `neck.getChild("head")` | `head` is under `neck > upper` |
| StonehornGoatModel | `head.getChild("left_horn")` / `right_horn` | three siblings: `left_horn_base/mid/tip`, `right_horn_base/mid/tip` |

Both are fixed. The goat's horn sway now drives the base segment, which is correct because
the mid and tip are siblings rather than children.

## Regression guard

`tools/check_model_parts.py` parses every `EntityModel` in the mod, rebuilds the part tree
from `addOrReplaceChild` calls, and asserts that every constructor `getChild` path resolves.
It reports all six models as OK. This runs in seconds and catches exactly the class of bug
that blacked out the client.

Note on the check: the tree is keyed by **part name**, not Java variable name. Generated code
binds `PartDefinition tail_tail_mid = tail.addOrReplaceChild("tail_mid", ...)`, and
`getChild("tail_mid")` is correct even though the variable is named differently. An earlier
version of the checker keyed on variable names and produced false failures.

## Entity model and layered texture rebuild (`98fc872` / `de74dec`)

Following the `getChild` path fix, all five spirit beasts and the three cultivation settlers
received a full geometry, UV, and texture overhaul across commits `98fc872` and `de74dec`:

- **Integer Box UV alignment (`98fc872`)**: Aligned all `BoxSpec` dimensions (`w`, `h`, `d`)
  to exact positive integers and all pivots/offsets to multiples of `0.5`, and corrected
  `box_extent` width allocation to `2*(w+d)` with standard vanilla face mapping so neither
  `CubeListBuilder.addBox` nor Blockbench Box UV `floor()` truncates into transparent texels.
- **Angled sub-bone hierarchies (`de74dec`)**: Rebuilt all six `EntityModel` trees with
  multi-joint child bones using `PartPose.offsetAndRotation`:
  - `SpiritFoxModel`: multi-stage tapered muzzle, wide splayed ears with inner fluff and
    glowing tips, digitigrade 3-joint legs (`thigh -> shin -> paw`), and a 3-plume fan-splayed
    spirit tail with jade-flame tips.
  - `WindWolfModel`: broad chest and tapered waist, multi-layered windswept mane and shoulder
    wind-blade fins, digitigrade predator legs, and a 3-joint tail.
  - `StonehornGoatModel`: 4-segment helical ram horns curling up, out, back, and forward with
    golden ley-line veins, angled goatee, sloped rock shoulder armor, and cloven hooves.
  - `EmberCraneModel`: 4-segment S-curved neck, cinnabar crown and pointed beak, layered
    angled primary/secondary wing feathers, fan-splayed tail plumes, and 3-joint legs with talons.
  - `CrystalTurtleModel`: octagonal tiered dome carapace, 6 radiating angled spirit crystal
    spires, horned/bearded dragon-turtle head, splayed flippers with claws, and spiked tail.
  - `CultivationSettlerModel`: layered silk robes, wide sleeves, topknot with jade hairpin,
    and role-specific props.
- **Procedural layered textures (`de74dec`)**: Replaced flat noisy fills in
  `tools/build_ecosystem_textures.py` with shaded silk drapery folds, warm skin gradients,
  lustrous hair strands, multi-tone fur, stone plates, and glowing crystal facets.
